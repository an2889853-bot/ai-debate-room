# 사용 설명서 — 화면·옵션·표시 읽는 법

설치가 끝난 뒤 보는 문서입니다 (설치는 [GUIDE.md](GUIDE.md)). 화면은 **왼쪽 사이드바(설정)** 와 **가운데 채팅(토론)** 으로 나뉩니다.
기본값은 "아무것도 안 만지고 질문만 쓰면 되는" 쪽으로 맞춰져 있습니다: 3단계 토론, Claude가 먼저, 도구 꺼짐, 독립 평가 켜짐.

## 한 라운드가 돌아가는 순서

```
질문 → [A · 최초 답변] → [B · 검토: 지적 1, 2, 3 … + 판정] → [A · 최종 답변: 반영/반박 번호별] → [B · 독립 평가: PASS / NEEDS_WORK]
                                                                              (NEEDS_WORK면) → [A · FINAL 2] → [B · 재평가]
```
A/B는 "먼저 답하는 AI"와 그 상대입니다. 5단계로 늘리면 검토 뒤에 `[A · 반박·수정] → [B · 재검사]`가 끼어듭니다. 매 단계는 **독립 호출**이라 모델에 기억이 없고, 앱이 지금까지의 전체 기록을 매번 다시 넣어 줍니다.

## 사이드바 옵션 — 위에서 아래 순서

### 💬 대화

| 옵션 | 하는 일 | 참고 |
|---|---|---|
| 🆕 새 대화 | 현재 대화를 닫고 빈 상태로 | 저장은 이미 돼 있음 |
| 저장된 대화 | 이전 대화를 열기. 열면 이어서 질문 가능 — 이전 라운드의 질문+최종 답변이 참고 맥락으로 들어감 | "(구 기록)"은 옛 형식 |
| ⬇ 이 대화 .md 내려받기 | 마크다운 파일로 저장 | 공유·보관용 |
| 삭제 | 두 번 확인 후 삭제. 도구를 켰던 대화면 그 작업 폴더도 같이 삭제 | |
| 📊 통계 | 저장된 대화 전체: 라운드 수, AI별 평균 시간, 토큰·비용, 반영 계약·평가 결과 집계 | |
| 📁 작업 폴더 | 도구를 켠 라운드가 쓴 `workspace\` 폴더 목록·용량, 대화에 연결 안 된 폴더 정리 | |

### 모드 — 역할 지시문 세트

| 모드 | 언제 | 특징 |
|---|---|---|
| **일반 토론** (기본) | 아무 주제 | 사실·논리·대안 중심 검토 |
| **코드 리뷰** | 코드를 첨부했을 때 | 정확성 → 보안 → 성능 → 가독성 순, 지적에 코드 위치·심각도, 최종은 수정 코드 전체 |
| **PLC 검증** | GX Works2 / Q 시리즈 래더 | 인터록·자기유지·타이머·디바이스 할당·비상정지·이중 코일 체크리스트, 랭 단위 설명, 시험 절차 |
| **투자 분석** | 시장·종목 판단 | 가정/시나리오/리스크 분리, 정보 제공용 문구, 웹 검색을 켜면 최신 수치를 확인하고 출처 표기 |

모드는 "무엇을 검토할지"만 바꿉니다. 토론 구조(단계·계약·평가)는 모든 모드에서 같습니다.

### 🛠 도구 — 웹 검색 · 파일·명령 · 코드 실행 (접혀 있음, 기본 전부 꺼짐)

| 옵션 | 기본 | 켜면 | 주의 |
|---|---|---|---|
| 🔬 코드 블록 실제 실행 | 꺼짐 | 답변 속 ```` ```python ```` 블록을 실제로 실행해 결과(exit 코드·출력)를 다음 단계에 증거로 붙임. 꺼져 있어도 **문법 검사**는 항상 함 | 모델이 쓴 코드가 이 PC에서 돕니다 |
| 🌐 웹 검색 허용 (실시간 확인) | 꺼짐 | Claude는 WebSearch/WebFetch, GPT는 web_search. 검색한 사실엔 출처 URL·확인 시각을 적게 하고, 검색 기록이 대화에 남음 | 느려지고 사용량 증가 |
| 검색 범위 | 최초 답변 + 평가 | **최초 답변 + 평가**: 첫 답이 검색, 검토·반박은 그 기록을 재사용, 평가자가 다시 확인 (권장) · **최초 답변만** · **전체 단계**: 단계마다 검색 (실측 4단계 11분·토큰 100만+) | 웹이 꺼지면 비활성 |
| 🛠 파일·명령 허용 | 꺼짐 | 대화별 `workspace\` 폴더 안에서 파일 읽기/쓰기 + 허용 목록 명령(python·pytest·pip·git·ls·dir·cat·type·echo·mkdir)만. 실행한 명령·결과·파일 변경이 기록에 남고 단계마다 git 커밋 | **AI 코드가 이 PC에서 실제 실행됨.** 허용 목록 안이라도 python은 임의 코드. 믿을 수 있는 작업에서만 |
| 단계당 도구 호출 권고 상한 | 8 (평가자 5) | 지시문으로 주는 권고치 | 강제는 아님 (CLI에 옵션 없음) |

언제 켜나: **뉴스·시세·최신 버전**처럼 최신 사실이 핵심이면 🌐, **코드를 짜고 돌려봐야** 하면 🛠(+🔬). 설계 검토·문서 피드백·논증처럼 근거가 이미 질문·첨부 안에 있으면 끄는 편이 낫습니다 — 검색이 추론을 밀어내고 두 AI가 같은 검색 결과에 묶여 독립 검토가 약해집니다.

### 순서

| 옵션 | 기본 | 설명 |
|---|---|---|
| 순서: 기본 / 직접 편집 | 기본 | 직접 편집은 표에서 행(AI, 역할)을 추가·삭제해 임의 순서. 첫 행은 최초 답변, 마지막은 최종 정리(또는 그 뒤 평가) |
| 대화 단계 수 | 3단계 | **3단계** 최초 → 검토 → 최종 (빠름) / **5단계** 최초 → 검토 → 반박·수정 → 재검사 → 최종 (더 깊게) |
| 먼저 답하는 AI | Claude | 상대가 검토(5단계면 재검사도)를 맡음 |
| 최종 정리 AI | 먼저 답한 AI와 같게 | 최종 답변을 쓸 AI |
| 검토 ↔ 반박 라운드 수 | 1 | 5단계일 때만. 2·3이면 검토↔반박이 반복돼 7·9단계 |
| 조기 종료 | 켜짐 | 검토 AI가 `[판정: 추가 수정 불필요]`라 하면 남은 검토 단계를 건너뛰고 바로 최종 |
| 단계마다 멈춰서 내가 끼어들기 | 꺼짐 | 켜면 단계가 끝날 때마다 멈춰 한마디 넣거나 방향을 바꿀 수 있음. 꺼져 있어도 진행 중 "⏸ 다음 단계 전에 멈춤"으로 언제든 |
| 🧑‍⚖️ FINAL 뒤 독립 평가 | 켜짐 | 최종 답변을 쓰지 않은 쪽 AI가 새 호출로 채점 (`PASS` / `NEEDS_WORK`), 문제는 `[지적 N]`으로. 호출 1회 추가 |
| NEEDS_WORK면 FINAL 1회 재작성 후 재평가 | 켜짐 | 평가자의 지적을 반영해 FINAL 2를 쓰고 다시 채점. 최대 1회 (호출 2회 추가) |

## 채팅 화면

### 입력
- 아래 입력창에 질문. 📎로 파일 첨부 — 텍스트·코드·PDF·이미지(`txt md csv json pdf log xml yaml toml ini cfg sql py js ts html css c h cpp java cs st il awl scl ps1 bat cmd png jpg jpeg gif webp bmp`)
- 텍스트/PDF는 본문으로(파일당 6만 자·전체 15만 자까지), 이미지는 긴 변 1568px로 줄여 매 단계 전달, **글자 없는 PDF(스캔·인쇄본)는 쪽 이미지로** 최대 12쪽
- 같은 대화에서 이어서 질문하면 이전 라운드의 질문+최종 답변이 참고 맥락으로 들어감

### 진행 중 조작
| 버튼 | 뜻 |
|---|---|
| ⏸ 다음 단계 전에 멈춤 | 지금 단계는 끝까지 받고, 그다음 단계로 가기 전에 멈춤 |
| ⏹ 중단 | 즉시 중단 (나중에 "▶ 이어서 진행" 가능) |
| (멈춘 상태) 여기서 한마디 | 텍스트를 넣고 ▶ 계속 → `[사용자 · 개입]`으로 기록되어 이후 단계가 최우선 반영 |
| ▶ 계속 / 🔁 직전 단계 다시 생성 / ⏭ 바로 FINAL로 / ⏹ 중단 | 멈춘 상태의 선택지 |
| ▶ 이어서 진행 (중단된 지점부터) | 중단·오류로 끝난 라운드를 다음 단계부터 재개 |

### 말풍선과 표시 읽는 법
| 표시 | 뜻 |
|---|---|
| 🟠 Claude / 🟢 GPT / 🧑 사용자 | 발언자. 중간 단계는 접혀 있고 **🏁 FINAL**은 주황 상자 |
| 캡션 `model: … · 12.0k→6.8k 토큰 · API 환산 $0.12` | 실제 적용 모델, 입력→출력 토큰, 비용 환산(구독이면 실제 과금 아님). GPT 토큰은 도구를 켰을 때만 잡힘 |
| `fable 크레딧 필요 → opus로 대체` | 구독에 없는 모델이라 자동 대체됨 |
| 🧾 `Claude · Review의 지적 3건 전부 처리 — 반영 2 · 반박 1` | **반영 계약**: 검토의 `[지적 N]`마다 답변자가 `[반영 N]`/`[반박 N]`을 썼는지 프로그램이 검사. 빠지면 같은 단계를 1회 재요청("재요청 1회") |
| ⚠ `미처리 지적: Claude · FINAL → 2` | 재요청 후에도 판정이 빠진 번호. FINAL을 그대로 믿기 전에 그 항목을 확인 |
| ✅ `검토 지적 N건 전부 처리됨` | 라운드 전체가 계약을 통과 |
| 🔬 `코드 검사 2개 블록 — OK 1 · 실패 1` | 답변 속 코드 블록의 문법/파싱(실행을 켰으면 실행) 결과. 실패는 상세가 펼쳐짐 |
| 🧑‍⚖️ `독립 평가: PASS (FINAL 재작성 후 재평가)` | 평가 결과. NEEDS_WORK로 끝나면 경고 |
| 🛠 `도구 3회 — Bash 2 · WebSearch 1 · 거부 1` | 도구를 켠 단계가 실제로 돌린 명령·검색·파일 변경. "거부"는 허용 목록 밖 명령이 차단된 것 |
| 🗜 `이전 단계 2개를 요약해 전달` | 기록이 길어 앞부분을 요약해 넣었음 |
| ⏩ | 검토 AI가 '추가 수정 불필요'로 판정해 건너뜀 |
| ⏱ `합계 127s (3단계) · 토큰 23.1k · API 환산 $0.12` | 라운드 합계 |
| 📁 `작업 폴더: …` | 도구를 켠 라운드가 쓴 폴더. 단계마다 git 커밋되어 `git log`로 되돌릴 수 있음 |
